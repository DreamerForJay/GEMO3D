# Figure and content provenance

The site is a static research page. All new figures use existing GEMO3D results;
no detector was retrained or rerun and no result images were generated by AI.

## Method diagram

The Method section uses the detailed English architecture figure supplied by
the author, `assets/architecture-en.png`. It presents the same online inference
and offline training stages in English. Selecting the figure opens the full-size
image.

## Quantitative results

The two CSV files in `assets/data/` were copied without modifying numeric values
from `/home/e114/mono3d_comparison_fr/plots/compare_all/`:

- `compare_bin_summary_common.csv` → `depth-bins.csv`
- `compare_overall_summary_common.csv` → `overall.csv`

This is the 165-object common-matched evaluation. The other local directory
`compare_common_ci95` contains a 128-object evaluation and is not used for the
quantitative table or plots.

Run `python3 docs/tools/plot_results.py` from the repository root to regenerate
the English SVG plots (requires Matplotlib). Points use `depth_center`,
`y_mean`, and the stored `y_ci95` (1.96 × SEM), without refitting or smoothing.
Depth RMSE uses `rmse_from_zero`; yaw, 3D center error and BEV IoU use `mean`.
The website rounds the full-precision values to two decimal places.

The old HTML table had small discrepancies relative to this CSV. The new table
explicitly identifies its localization metrics as recomputed from these stored
summaries. For example, MonoDETR yaw error is 1.79° (previous HTML: 1.73°),
MonoDGP depth RMSE is 1.41 m (previous HTML: 1.40 m), and both MonoAMNet and
MonoDGP BEV IoUs round to 0.47 (previous HTML: 0.46). FPS values remain those
reported on the original page, measured separately on 100 images. These CSV
results should not be described as a verbatim reproduction of the paper table.

## Qualitative examples

`tools/render_examples.py` reconstructs existing predictions using:

- Predictions: `/home/e114/mono3d_comparison_fr/pairs/gemo3d_pairs.csv`
- Common-object selection: intersection of the four `*_pairs.csv` files
  in the same directory (128 objects in the available pair files).
- Images, labels and calibration: `/home/e114/data/KITTIDataset_Carla/training/`

The three samples are the objects nearest 10, 20, and 30 m ground-truth depth:
frames `000151`, `000090`, and `000023`. Selection does not use prediction error.
Ground-truth dimensions, position and yaw were verified against the associated
KITTI label file before rendering. Predicted corners use KITTI bottom-center
coordinates, the stored predicted dimensions and yaw, and that frame's `P2`.
The blue projected box is GEMO3D. The orange dashed BEV footprint is ground truth.
The figure's inset is an enlarged region of the same frame; the BEV grid is 1 m.

These are qualitative examples from the stored front-view run, not a claim to
reconstruct the 165-object evaluation set from the currently available pair
files. `assets/data/examples.json` records the selected poses and calibration.
SVG files embed their RGB image, so they do not depend on local absolute paths.

## Overview video and method animations

The overview video is hosted on YouTube (https://youtu.be/WyC59Sddipc). It was
rendered with HyperFrames from the figures in this folder; every number it shows
comes from the manuscript table.

`assets/loop-pinhole.mp4`, `assets/loop-ratio.mp4` and `assets/loop-reconstruct.mp4`
are silent, cropped excerpts of that same video (scenes "Initial depth", "The key
idea" and "3D reconstruction"), re-encoded at 1280 px wide for the Method section.
They illustrate the geometry; they are not new detection outputs.
